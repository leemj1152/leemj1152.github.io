CASE 02 / VISION-LANGUAGE MODEL

오탐이 줄어든 자리에서 미탐까지 확인하기

사람 확인 단계의 VideoChat과 Qwen 후보를 동일한 입력 조건으로 비교했습니다. 줄어든 오탐과 새로 발생한 미탐을 함께 분석해 모델 교체의 판단 근거를 정리했습니다.

MY ROLE

비교 평가 · 오류 분석 · API 연계 점검

TOOLS

VideoChat · Qwen · PyTorch · OpenCV

IN THIS CASE

01. 문제와 역할02. 해결 과정03. 결과와 판단04. 배운 점

01 문제와 역할

사람과 비슷한 물체가 사람으로 통과하면 불필요한 후단 분석과 알림이 늘어납니다. 반대로 사람 확인 기준을 엄격하게 바꾸면 실제 사람을 추가로 놓칠 수 있습니다.

모델 후보를 선택할 때 두 오류를 함께 확인하고자 했습니다. 사람 확인과 폭행·쓰러짐 판정을 구분하고, 같은 입력에 대한 판정이 어떻게 달라지는지 비교했습니다.

동일 입력 구성→후보별 추론→판정 차이 분석→연계 경로 점검

02 해결 과정

입력과 출력 조건을 먼저 맞췄습니다.

이미지 전처리와 영상 샘플링 조건을 비교하고, 이미지 텐서와 영상 프레임·인덱스가 일치하는지 확인했습니다. 모델 응답에서 최종 판정을 읽어내는 파싱 과정도 점검했습니다.

판정이 바뀐 사례를 따로 살폈습니다.

사람 표본과 비사람 표본을 구분해 기존 모델과 후보 모델의 결과를 비교했습니다. 비사람 오통과가 줄어든 사례와, 기존에 통과하던 사람이 새롭게 누락된 사례를 함께 분석했습니다.

운영 연계 조건을 확인했습니다.

기존 API의 요청·응답 형식을 유지할 수 있는지 점검하고, 모델 실행 경로와 복구 절차를 정리했습니다. 이미지와 영상 입력을 나눠 추론·응답 파싱을 검증했습니다.

03 결과와 판단

OBSERVED

오탐 감소와 미탐 증가를 함께 확인

재사용한 사람 확인 표본에서 비사람 오통과가 감소했습니다. 동시에 실제 사람을 추가로 놓친 사례가 있어, 두 결과를 함께 모델 선택의 근거로 정리했습니다.

FOLLOW-UP

평가 단계와 추가 검증 조건 구분

사람 확인 단계의 결과와 전체 이벤트 탐지 결과를 구분했습니다. 새로운 현장과 전체 스트림 경로에서 추가로 확인할 오류 유형을 구체화했습니다.

04 배운 점

줄어든 오류만큼, 새로 생긴 오류도 설명할 수 있어야 했습니다.

비교 조건을 맞추고 판정이 달라진 사례를 추적하면서 모델의 장단점을 구체적으로 파악했습니다. 이후 평가에서도 오탐·미탐의 변화와 실제 운영 경로의 영향을 함께 살피고 있습니다.
