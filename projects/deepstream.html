CASE 01 / SYSTEM ENGINEERING

모델을 실시간 영상 시스템으로 연결하기

기존 DeepStream 모듈에 모델과 이벤트 처리 경로를 연결하고, 실제 입력과 자원 사용량을 함께 계측하며 다채널 환경의 병목을 개선했습니다.

MY ROLE

모델 이식 · 처리 경로 개선 · 운영 검증

TOOLS

DeepStream · TensorRT · Python · Docker

IN THIS CASE

01. 문제와 역할02. 해결 과정03. 결과와 판단04. 배운 점

01 문제와 역할

영상 AI 시스템에서는 모델의 단독 추론 속도만으로 운영 성능을 설명하기 어렵습니다. 영상 수신과 전처리, 후단 분류, 이벤트 저장이 함께 실행되면 다른 단계에서 병목이 발생할 수 있습니다.

저는 기존 팀이 개발한 DeepStream 모듈을 기반으로 로컬 모델과 이벤트 흐름을 통합했습니다. 변경 전후의 처리 속도와 GPU·메모리 사용량을 비교하고, 입력 장애와 추론 오류를 구분해 확인했습니다.

영상 수신→검출·전처리→후단 판단→이벤트·저장

02 해결 과정

처리 경로를 단순화했습니다.

검출·포즈 2단계 구성을 단일 PGIE 구성으로 전환하고, GPU 전처리와 분류 배치 처리를 적용했습니다. 반복적인 프레임 접근을 줄이는 작업과 이벤트별 미디어 저장 연계를 함께 진행했습니다.

실제 수신 상태를 기준으로 계측했습니다.

등록된 채널 수와 실제 수신 채널 수를 나눠 기록했습니다. FPS, GPU 사용률, 프로세스 메모리, 전력을 비교하고 이벤트 미디어가 끝까지 저장되는지도 확인했습니다.

사람이 등장하는 장면으로 부하를 확인했습니다.

별도의 다채널 시험에서는 사람이 등장하는 입력을 사용하고, 같은 GPU에서 VLM이 함께 실행될 때의 검출 속도와 응답 지연을 확인했습니다. 입력 수신 실패와 모델 처리 지연을 구분해 병목을 추적했습니다.

03 결과와 판단

OBSERVED

처리 속도 유지와 자원 사용 감소

운영 비교 구간에서 추론 속도를 유지하면서 GPU·메모리 사용량이 줄어든 것을 확인했습니다. 모델과 게이트 개선이 함께 반영된 구성 전체의 결과로 해석했습니다.

FOLLOW-UP

다음 검증 지점 구체화

다채널 시험 중 발생한 VLM 타임아웃을 확인하고, 검출 FPS와 후단 대기·응답 지연을 나눠 분석했습니다. 장시간 시험에서 확인할 조건을 정리했습니다.

04 배운 점

운영 성능은 입력부터 최종 이벤트까지 연결해서 봐야 했습니다.

모델의 처리 속도, 실제 수신 상태, 후단 지연과 저장 완료는 서로 다른 지표입니다. 각 단계를 구분해 계측해야 개선이 필요한 위치를 찾고 변경의 효과를 설명할 수 있다는 점을 배웠습니다.
